# 基于多智能体协同的森林火险智能分析与预警平台设计与实现

> 论文类型：本科毕业设计（软件工程方向） · 成果系统：焰哨（FlameSentry）森林火险智能分析与预警平台
> 说明：本文以真实可运行的系统为事实依据撰写，全部插图源文件保存于 docs/puml 目录，系统界面截图保存于 docs/images 目录。

## 摘  要

森林火灾是我国破坏性最强的自然灾害之一，云南省地处干热河谷与横断山脉交错地带，冬春季节干旱少雨，长期位居全国森林火险高发区前列。传统火险信息化系统以"被动展示"为主，普遍存在查询门槛高、领域知识分散、分析依赖人工、报告标准不一等问题，难以支撑快速决策。针对上述问题，本文设计并实现了一个基于多智能体协同的森林火险智能分析与预警平台，将自然语言交互、检索增强生成与状态图驱动的多智能体编排引入森林火险治理场景。

系统采用前后端分离架构。后端以异步接口框架为骨架，以支持空间类型的数据库承载历史火点、预测火险与行政边界数据；核心编排层由八个节点构成的状态图驱动：任务拆解节点产出结构化执行计划并约束关键步骤不可裁剪，数据查询与知识检索节点并行执行、经汇聚屏障后进入空间热点分析，报告生成节点按刚性模板产出分析报告，评审节点以低温度模型评审与确定性硬护栏双重把关，最终经人工审批闸口定稿。统一模型调用层提供指数退避重试、熔断与多提供商降级能力，保证外部模型服务不可用时系统仍可完整运行。前端基于渐进式框架与开源地图引擎实现作战大屏、智能查询、知识库问答、协作中心、报告中心与系统管理六类界面，支持实时进度推送与全链路语音交互。

系统测试从功能、接口、编排回归与安全四个维度展开：功能与接口测试覆盖全部核心业务路径，编排回归评估基于金标用例集验证任务拆解、路由与报告完成度，安全测试验证令牌鉴权与用户数据隔离。结果表明，系统在真实数据环境下运行稳定，能够自动完成"数据查询—空间分析—知识检索—报告生成"的决策闭环，为森林火险治理提供了一种可落地、可演示、可维护的工程化方案。

**关键词**：多智能体协同；森林火险；检索增强生成；状态图编排；实时交互

## Abstract

Forest fire is one of the most destructive natural disasters in China. Yunnan Province, located in the interleaving zone of dry-hot valleys and the Hengduan Mountains with a dry winter–spring climate, has long been among the most fire-prone provinces. Traditional fire-risk information systems are mostly passive dashboards, suffering from high query barriers, scattered domain knowledge, labor-intensive analysis, and inconsistent reporting. To address these problems, this thesis designs and implements an intelligent forest-fire analysis and early-warning platform based on multi-agent collaboration, introducing natural-language interaction, retrieval-augmented generation, and state-graph-driven multi-agent orchestration into forest fire management.

The system adopts a front–back separated architecture. The back end is built on an asynchronous API framework and a spatial database that stores historical fire points, predicted fire risks, and administrative boundaries. The core orchestration layer is driven by a state graph of eight nodes: a task-parsing node produces a structured execution plan with mandatory steps; the data-query node and the knowledge-retrieval node run in parallel and converge at a join barrier; the spatial analysis node clusters fire points into hotspot grids; the report node generates analysis reports following a rigid seven-section template; a review node applies both low-temperature LLM review and deterministic hard guardrails; and a human-approval gate finalizes the report. A unified LLM invocation layer provides exponential-backoff retry, circuit breaking, and multi-provider degradation, keeping the system fully functional even without external model services. The front end, based on a progressive framework and an open-source map engine, provides six interfaces including an operations dashboard, smart query, knowledge-base Q&A, agent collaboration center, report center, and system administration, with real-time progress streaming and full-chain voice interaction.

System testing covers four dimensions: functionality, interfaces, orchestration regression, and security. Functional and interface tests cover all core business paths; orchestration regression is validated on a golden case set measuring task decomposition, routing logic, and report completion; security tests verify token-based authentication and user data isolation. Results show that the system runs stably in a real-data environment, automatically closes the decision loop of "query–analysis–retrieval–reporting", and offers an engineering-feasible solution for intelligent forest fire management.

**Key words**: multi-agent collaboration; forest fire risk; retrieval-augmented generation; state-graph orchestration; real-time interaction

# 第1章 绪论

## 1.1 研究背景与意义

森林火灾具有突发性强、蔓延速度快、破坏范围广的特点，是威胁森林资源、生态系统与人民生命财产安全的重大自然灾害。云南省地处我国西南边陲，境内横断山脉与干热河谷交错分布，冬春季节（尤其是二月至五月）干旱少雨、风大物燥，森林火险等级长期居高不下，是我国森林火灾最高发的省份之一。森林火险治理涉及火情监测、风险评估、资源调度与应急处置等多个环节，对信息系统的依赖程度日益提高。

然而，现有森林火险信息化系统多以可视化大屏与静态报表为主，业务价值存在明显瓶颈。其一，查询门槛高：业务人员若要获得"某州市某月份火险排名"这类结论，需要掌握结构化查询语言或专业地理信息系统软件，一线人员难以直接使用。其二，知识沉淀不足：防火条例、处置规范、国家标准等文档散落在本地各处，火情发生时难以及时检索到权威依据。其三，分析依赖人工：从数据查询、空间分析到撰写处置报告的完整链条均由人工完成，耗时长且质量因人而异。其四，系统割裂：数据大屏、数据查询与报告撰写分属不同工具，无法形成决策闭环。

近年来，以大语言模型为代表的人工智能技术取得突破性进展[1][2]，检索增强生成[3]使模型能够基于外部知识回答领域问题，多智能体编排技术[4][5][6]使复杂任务能够被拆解为多个智能体分工协作完成。将这些技术与地理空间数据能力结合，构建一个"自然语言驱动、多智能体分工协作、知识库增强"的森林火险智能决策平台，在技术上已经成熟，在业务上具有明确价值。

本课题的意义在于：面向云南省森林火险治理的真实场景，完成从传统可视化大屏到智能决策平台的完整演进；将自然语言作为统一交互入口，降低业务人员使用门槛；将"查询—分析—检索—报告"链条交由多个智能体自动执行，缩短决策周期；同时通过可靠性工程设计保证系统在真实环境中稳定可用，形成可答辩、可演示、可维护的完整工程成果。

## 1.2 国内外研究现状

### 1.2.1 国外研究现状

智能体（Agent）研究由来已久。Wooldridge 与 Jennings 早在二十世纪九十年代就对智能体的弱定义与强定义进行了系统阐述[7]，奠定了多智能体系统的理论基础。2017 年，Vaswani 等提出 Transformer 架构[1]，以自注意力机制建模长距离上下文依赖，成为后续大规模预训练模型的标准骨架。Brown 等于 2020 年提出 GPT-3[2]，验证了大规模语言模型少样本学习的涌现能力；Ouyang 等通过基于人类反馈的指令微调[8]显著提升了模型遵循指令的能力；Wei 等提出思维链提示[9]，增强了模型在复杂推理任务上的表现。

在模型能力外部化方面，Lewis 等提出检索增强生成框架[3]，将参数化知识与外部知识库解耦，显著降低了幻觉问题；Karpukhin 等提出的稠密段落检索[10]为向量语义检索提供了经典方案。在工具使用与自主行动方面，Yao 等提出 ReAct 范式[4]，将推理与行动交替执行；Schick 等提出 Toolformer[11]，使模型学会自主调用外部工具。在自我改进方面，Shinn 等提出 Reflexion 机制[12]，使智能体能够基于失败反馈进行反思重试。

多智能体协作方面，Park 等构建了具有记忆与反思能力的生成式智能体社会[13]；Wu 等提出 AutoGen 多智能体对话框架[14]；Hong 等提出 MetaGPT[15]，将软件公司的标准作业流程引入多智能体协作。Wang 等与 Xi 等分别对基于大语言模型的自主智能体进行了系统综述[5][6]，指出任务规划、记忆、工具使用与多智能体协作是该方向的核心议题。此外，Fielding 的表述性状态转移架构约束[16]为现代 Web 服务接口设计提供了方法论基础。

### 1.2.2 国内研究现状

国内在大语言模型及其应用方向的研究紧随国际前沿并形成自身特色。车万翔等系统论述了大模型时代自然语言处理面临的挑战、机遇与发展路径[17]，指出语言模型正在从任务专用走向通用基座；舒文韬等从原理、实现与发展三个维度对大型语言模型进行了全面梳理[18]；张钹等提出迈向第三代人工智能的技术路线[19]，强调将知识驱动与数据驱动相结合，这一思路与本文"模型推理 + 知识库检索 + 确定性护栏"的混合设计相契合。在中文信息处理基础方面，黄昌宁等对中文分词技术进行了系统回顾[20]，为本文知识库检索中的中文分词通道提供了依据。

在领域应用层面，国产大模型生态快速成熟：通义千问系列模型先后发布技术报告[21][22]，提供了开放接口与向量、多模态系列模型；DeepSeek 系列模型以低成本高性能著称[23]，并可通过云服务接口获得。空间信息领域，国产地理信息系统的理论与工程体系较为完善[24][25]，地理与时序加权回归模型（GTWR）由 Huang 等提出[26]，被广泛用于火险等时空非平稳关系的建模，本文预测火险数据即来源于基于该模型的预测结果。在火情遥感监测方面，Giglio 等发展的 MODIS 主动火点检测算法[27]是全球火点数据产品的基础，本文历史火点数据即取自其数据产品。总体来看，将大模型与多智能体技术应用于森林火险治理的完整工程实践仍较少，本文工作具有一定的探索价值。

## 1.3 研究内容与主要工作

本文的研究对象是面向森林火险治理的智能分析与预警平台，核心研究内容可抽象为"如何以状态图编排多个智能体，在保证可靠性与可控性的前提下，自动完成自然语言驱动的数据分析任务链路"。围绕这一抽象，本文完成的主要工作如下：

1. 完成系统总体设计与数据库设计。构建前后端分离的六层架构，设计覆盖业务数据与平台数据共十三张数据表，其中空间数据表采用点与多边形几何字段并建立空间索引；设计覆盖认证、大屏、查询、知识库、协作、报告、管理与视觉语音八大模块的接口体系。
2. 设计并实现状态图驱动的多智能体编排机制。包括结构化执行计划的产出与约束、数据查询与知识检索的并行执行与汇聚屏障、查询为空时的反思重试、报告的模型评审与确定性硬护栏双重把关、基于中断恢复机制的人工审批闸口，以及节点级实时进度推送。
3. 实现检索增强问答与可靠性工程。包括扫描版文档的四层文本解析兜底、中文感知切分、向量与关键词双通道混合检索、重排序精排及其降级方案，以及覆盖重试、熔断、多提供商降级与规则兜底的统一模型调用层。
4. 实现前端六类交互界面与全链路语音交互。包括基于开源地图引擎的作战大屏（聚合、热力图、量测、导出）、智能查询四维结果联动、知识库问答、协作中心流水线可视化、报告管理与系统管理，以及录音识别与语音播报的完整链路。
5. 建立多维度系统验证体系。包括黑盒功能测试、接口测试、基于金标用例集的编排回归评估与安全测试。

# 第2章 相关技术与理论基础

## 2.1 大语言模型技术

### 2.1.1 Transformer 架构

Transformer 是当前大语言模型的标准基础架构[1]，其基本结构如图 2-1 所示。

![图 2-1 Transformer 模型基本结构示意图](puml/png/fig2-1_transformer.png)

图 2-1 Transformer 模型基本结构示意图

由图 2-1 可知，Transformer 由编码器与解码器堆叠构成，其核心是自注意力机制：模型将输入序列映射为查询、键、值三组向量，通过缩放点积注意力计算词元间的关联权重[28]，从而以并行方式建模任意距离的上下文依赖。解码器额外引入掩码自注意力与交叉注意力，使输出序列能够逐词元自回归生成。该架构天然适配文本生成任务，是本系统报告生成、意图识别与知识问答等能力的模型基础。

### 2.1.2 指令微调与国产开源模型生态

基础语言模型经过指令微调与人类反馈对齐后才能稳定遵循用户指令[8]。近年来国产模型生态快速成熟：通义千问系列提供对话、向量、视觉与语音全谱系模型并开放标准接口[21][22]；DeepSeek 系列模型在保持低成本的同时达到先进推理水平[23]。本系统采用兼容接口协议接入上述模型服务，对话模型支持在云端多提供商与本地部署之间切换，向量、视觉与语音模型则固定使用统一服务商以保证多模态能力稳定。

## 2.2 检索增强生成技术

大语言模型的参数化知识存在时效滞后与领域不足的问题，直接问答容易产生与事实不符的内容。检索增强生成[3]将"参数化知识"与"外部知识库"解耦：先从知识库中检索与问题相关的内容片段，再将其作为上下文交给模型生成回答，使回答有据可依。其基本流程如图 2-2 所示。

![图 2-2 检索增强生成（RAG）基本流程图](puml/png/fig2-2_rag.png)

图 2-2 检索增强生成（RAG）基本流程图

检索环节的质量决定回答质量。语义检索以稠密向量表达文本[10]，关键词检索以词项命中计数打分[29]，两者各有所长：前者擅长同义改写，后者擅长专有名词精确匹配。实践中普遍采用多通道召回后融合排序的策略，并可引入重排序模型对候选片段进行精排。本文知识库模块在此基础上针对中文场景增加了中文分词通道，并设计了重排序失败时的降级融合方案。

## 2.3 多智能体系统与状态图编排

### 2.3.1 从单智能体到多智能体协作

单个语言模型智能体可以借助工具调用完成简单任务[4][11]，但面对"查询数据、空间分析、知识检索、撰写报告"这类长链条任务时，单一上下文容易过载且错误会逐级放大。多智能体协作将任务拆解给职责单一的智能体，通过编排机制控制协作顺序与信息流动[5][6][14][15]。经典协作模式包括：交替推理与行动的 ReAct 范式[4]、基于失败反馈的反思重试[12]、生成后自我评审的评审循环，以及在关键决策点引入人工确认的人机协同控制[13]。这些模式构成本系统编排机制设计的理论基础。

### 2.3.2 状态图编排模型

将多智能体工作流建模为"状态 + 节点 + 边"的有向图是当前工程实践的主流方案：全局状态以键值结构承载任务上下文，节点是读取状态并返回增量的处理函数，边分为固定边与条件边，条件边依据状态决定后继节点，从而使图具备分支、循环与中断恢复能力。并行节点对同一状态键的写入需要通过归并函数合并，这是并发安全的关键。本系统采用的编排框架即基于该模型实现，其原理如图 2-3 所示。

![图 2-3 LangGraph 状态图编排原理示意图](puml/png/fig2-3_langgraph.png)

图 2-3 LangGraph 状态图编排原理示意图

## 5.3 智能体编排机制设计

编排机制是本系统的设计重心，其设计遵循"生成与执行分离、状态驱动流转、并发安全合并、关键产出受控"四项原则。

在状态设计上，全局状态以键值结构承载用户请求、执行计划、数据结果、空间结果、知识结果、报告正文与各类控制信息。其中步骤日志与知识结果两类键被声明为增量归并：并行节点只允许返回新增部分，由归并函数自动合并，从根本上避免并行写入互相覆盖。

在流转设计上，任务拆解节点产出结构化执行计划，计划以子任务列表表达，每个子任务包含类型、描述与是否必需标记。路由函数只读取计划而不读取执行状态，这一约束消除了并行波次下的状态竞争。执行计划存在两条硬约束：数据查询、空间分析与报告生成三个步骤被强制保留，即使用户请求只要求"查一下数据"，系统也会保证最终产出报告，避免"跑完无结论"。

在受控设计上，报告生成后依次经过评审与审批两道关口：评审环节将模型评审与确定性硬护栏并联，任一不通过即退回重写；审批环节通过中断机制将任务挂起并持久化，等待人工决策后恢复。中断状态的持久化使人工审批不再受限于单次请求生命周期，用户可以在任意时刻完成审批。

## 6.2 认证与权限模块实现

认证模块实现注册、登录与身份校验的完整闭环。注册环节先对用户名与邮箱查重，随后以盐值哈希算法对密码做单向散列后入库，任何明文口令都不落库；登录环节校验口令后签发带签名的访问令牌，有效期为二十四小时；此后每次请求在服务端解码校验令牌并加载用户身份，管理员接口在身份校验之上再校验角色。

数据隔离在本模块统一实施：查询历史、问答历史、知识文档、任务与报告的每一次读取都在查询构造层附加用户过滤条件，管理员可见全部数据。前端配合路由守卫实现体验层防护：未登录访问受保护页面时重定向到登录页并携带回跳地址，非管理员访问管理页时被拦截并提示。体验层防护与接口层校验互为冗余，任一层失效都不会造成数据越权。

## 6.3 智能查询模块实现

智能查询模块实现了"双引擎意图识别 + 三种意图执行器 + 四维结果生成"的完整链路。意图识别优先使用对话模型：提示词中内置全部州市清单、季节与月份映射关系及置信度枚举，要求模型以结构化格式输出意图与参数；模型输出解析失败或模型服务不可用时，降级为关键词规则引擎，规则引擎覆盖州市全称与常见简称的映射（例如简称"版纳"可映射到全称"西双版纳傣族自治州"）、年份月份解析、季节到月份区间的转换以及结果条数上限提取。

三种意图执行器分别处理历史火点查询（按日期区间过滤并按火辐射功率排序）、预测火险查询（按风险评分排序并按等级分档配色）与数据汇总（统计各州市火点数量并输出排名）。执行完成后，通用生成器将结果转换为空间数据格式，风险分档配色规则与前端保持同一来源，保证地图与图表颜色一致。查询结果与解析方式（模型或规则）一同写入历史记录，同一用户重复查询相同文本时仅更新时间与摘要，不产生重复条目。

## 6.4 知识库检索问答实现

### 6.4.1 文档解析与切分

文档处理流水线支持三种格式。纯文本直接读取；Markdown 先转换再剥离标签；便携文档格式的解析设计为四层兜底链：常规文本层解析器优先，失败后切换备用解析器，再退回到渲染式解析，最终以离线光学字符识别兜底。该链路解决了扫描版与自定义字体编码文档提取乱码的问题，实际测试中成功解析了采用自定义字体编码的国家标准文档。

解析得到的全文按递归切分策略分片，分片长度五百字符、重叠五十字符，分隔符按中文习惯优先采用空行、换行、句号与逗号，使分片边界尽量落在语义完整处。分片向量化后连同词元数一并落库，文档状态机经历待处理、处理中、就绪三态，失败时标记失败态并向用户展示原因。

### 6.4.2 混合检索与精排

检索环节采用双通道召回加精排的架构，流程如图 6-6 所示。

![图 6-6 知识库混合检索与重排序流程图](puml/png/fig6-6_hybrid.png)

图 6-6 知识库混合检索与重排序流程图

由图 6-6 可知，向量通道以问题向量与分片向量的余弦相似度打分，擅长语义改写场景；关键词通道以中文分词后的词项命中计数打分并对二字词加权，擅长专有名词精确匹配。两通道得分加权融合归一化后，若重排序服务可用则由重排序模型对候选分片精排，否则降级为倒数排序融合保留多通道原序。针对复杂问题，系统增加了自适应改写环：命中不足时由模型改写查询重新检索，最多三轮。回答生成环节的提示词明确要求引用来源编号，未检索到相关内容时模型被要求明确声明，而不是编造答案。问答结果支持流式输出，增量内容经事件流逐段推送至前端，完整内容在生成结束后统一落库。

### 6.5.2 并行执行与汇聚屏障

数据查询与知识检索并行执行以缩短任务总时长。并行引入的核心风险是状态竞争：两个节点若同时写同一状态键，后写者会覆盖先写者。本实现将步骤日志与知识结果两类状态键声明为增量归并模式——节点只返回新增片段，编排框架以追加方式合并，从机制上消除了覆盖问题。汇聚屏障由编排框架在图结构中天然保证：后续报告生成节点仅在两条并行支路全部完成后启动。

### 6.5.3 查询反思重试

查询环节存在三类常见失败：时间范围过窄、州市名称拼写偏差、视图模式不匹配。针对空结果，数据查询节点引入反思重试机制，流程如图 6-2 所示。

![图 6-2 数据查询反思重试流程图](puml/png/fig6-2_reflect.png)

图 6-2 数据查询反思重试流程图

由图 6-2 可知，查询为空时，模型先分析空结果的可能原因，再生成放宽后的参数（例如不限月份、扩大年份区间、修正州市名称），以新参数重查；重试轮次设有上限，超限后如实返回空结果说明，报告中如实声明数据缺失，避免编造。每一次尝试与空原因都记录在步骤日志中，供前端回放。

### 6.5.4 报告生成与评审循环

报告生成节点的提示词以刚性模板约束产出结构：报告必须包含执行摘要、数据来源与分析方法、火情数据分析、高风险区域识别、重点巡防建议、结论与展望及参考依据七个部分，标题顺序不可调整，篇幅不少于下限，且必须引用查询得到的真实数据。模板化带来的直接收益是报告质量稳定、风格统一，且评审环节可以按明确规则检查。节点支持流式产出，增量内容经推送通道实时到达前端；模型不可用时退化为固定模板报告，保证任务链路不断裂。

评审环节由模型评审与确定性硬护栏并联构成，流程如图 6-3 所示。

![图 6-3 报告评审循环流程图](puml/png/fig6-3_review.png)

图 6-3 报告评审循环流程图

硬护栏不依赖模型，以确定性规则一票否决：篇幅不足、必备章节缺失、缺少真实数据引用三者任一命中即判定不通过；硬护栏全部通过后，再由低温度模型评审结构与内容质量。未通过时，问题清单与修改建议注入重写提示词，报告节点带意见重写；重写轮次设上限，超限后强制放行并标注评审状态，避免死循环。该设计将"模型判质量、规则守底线"两种能力互补组合，评审结论稳定可复现。

报告评审通过后进入人工审批闸口，其实现依托编排框架的中断恢复机制，时序如图 6-4 所示。

![图 6-4 人工审批中断与恢复时序图](puml/png/fig6-4_hitl.png)

图 6-4 人工审批中断与恢复时序图

由图 6-4 可知，到达审批闸口时，状态机执行中断操作，将当前全部状态持久化到检查点存储，任务状态置为待审批；用户可在任意时刻提交通过、编辑或驳回决策，接口以同一线程标识恢复执行，状态机从中断点续跑。驳回决策携带的意见会被注入报告重写提示词，形成"人机协同改进"闭环。由于中断状态落在数据库中，服务重启后待审批任务依然可以恢复，不会丢失。

### 6.5.6 节点级实时进度推送

任务执行的可见性由事件流推送实现，机制如图 6-5 所示。

![图 6-5 实时进度推送（SSE）时序图](puml/png/fig6-5_sse.png)

图 6-5 实时进度推送（SSE）时序图

该机制有三个设计要点。其一，数据库是唯一事实源：工作线程将节点开始与结束状态以"先预写运行中、再覆盖终态"的方式写入步骤表，推送接口周期性刷新读取会话并将新增步骤推送给订阅者，推送与执行彻底解耦。其二，断线可重放：前端重连时携带最后收到的步骤序号，推送接口按序号补发缺失部分，保证事件不丢。其三，报告增量走独立的易失通道：生成中的半截内容不落库，终态以数据库落库内容为准，避免半截数据污染事实源。推送连接在任务完成后自动关闭，单连接设有最长存活时限。

### 6.5.7 编排状态持久化

状态机的检查点持久化到关系数据库中：每创建一个任务即分配唯一的线程标识，任务执行过程中的每一次状态变更都会写入检查点，使中断恢复、断点续跑成为可能。每个任务线程独享检查点连接以规避驱动层的线程安全问题；持久化组件不可用时自动降级为内存存储，此时人工审批在进程存活期内依然可用。服务重启时，仍在执行中的任务被标记为失败并说明原因，待审批任务不受影响。

# 第8章 总结与展望

## 8.1 工作总结

本文围绕森林火险预警业务中数据分散、研判依赖经验、报告编制耗时等现实问题，设计并实现了基于多智能体协同的森林火险智能分析与预警平台。主要工作总结如下。

第一，完成了业务调研与系统设计。梳理了历史火点、预测火险、州市边界等多源数据结构，提出分层架构与模块划分方案，完成了十三张业务表的数据库设计与统一风格的接口设计，为系统实现奠定了基础。

第二，构建了基于状态图的多智能体协同引擎。将任务解析、数据查询、空间分析、知识检索、报告生成、报告评审等环节建模为八个节点的状态图，通过并行分发汇聚提高执行效率，通过评审循环与人工审批保障产物质量，并借助检查点持久化支持任务恢复与历史回放。

第三，实现了面向大语言模型应用的可靠性底座。统一调用层提供指数退避重试、熔断保护、多提供商自动降级与规则兜底四级容错，使系统在模型服务波动甚至完全离线时仍能维持核心功能可用；每次调用附带提供商、模型与用量审计信息，为运维排查提供依据。

第四，实现了空间数据管理与智能分析能力。以空间扩展支撑五千余条历史火点与逐日逐月预测火险的存储索引，实现了网格聚类热点识别、缓冲区影响分析等空间算法，并以图层化地图组件与统计图表完成多维可视化呈现。

第五，实现了知识库检索增强与全链路实时交互。知识库支持四层文本解析兜底、中文感知切分、混合检索与重排精排；前端以服务端推送事件实现节点级任务进度、流式问答与报告增量呈现，并结合语音识别与合成完成了多模态交互闭环。

第六，建立了可重复的工程化保障。通过金标用例与确定性指标实现编排行为的回归管控，通过测试环境与测试用例体系验证了功能、接口与安全质量。

## 8.2 不足与展望

受开发周期与条件限制，系统仍存在以下不足，有待在后续工作中改进。

第一，向量检索存储有待升级。当前嵌入向量以结构化文本形式存储于分片表中，相似度计算在应用层完成，在知识库规模持续增长后检索效率将成为瓶颈。系统已预留向量扩展依赖，后续应将向量列迁移至数据库向量索引，实现存储与检索的数据库内闭环。

第二，接口级自动化测试尚未体系化。当前接口验证以人工执行与交互式文档为主，编排回归已实现自动化，但覆盖全部路由的接口自动化用例仍需补齐，以支撑持续集成流水线。

第三，运行日志为进程内存缓冲。系统日志采用环形缓冲存储于内存中，服务重启后历史日志丢失。后续应接入集中式日志存储与结构化追踪，将可观测性能力与业务进程解耦。

第四，火险预测依赖离线模型产物。预测数据来自地理加权时空回归模型的离线计算结果，系统未集成在线训练与滚动更新机制，预测时效性受制于数据导入周期。

展望未来，系统可从三个方向深化：其一，接入遥感影像与多源观测数据，结合视觉识别能力向灾情感知一体化演进；其二，扩展智能体工具生态，通过标准化工具协议接入更多外部数据与业务系统，提升协同分析的覆盖面；其三，探索面向防火业务的轻量化模型部署方案，在保障数据安全的前提下降低对外部模型服务的依赖。

系统的研究与实践表明，多智能体协同与检索增强生成技术在垂直业务领域具有切实的应用价值：在合理的编排设计与可靠性设计之下，大语言模型应用可以同时获得智能水平与工程稳定性，为智慧应急领域的智能化建设提供了可借鉴的工程路径。
